1. Assume a virtual circular ring with numbers of big enough range. (In production: 0-$10^6$)
	![Consistence Hashing 1.svg](Consistence%20Hashing%201.svg)
2. A hash function ($H_{X}$) 
	- Range: \[0,32]
	- For every server, compute it's hash value & put the server on the ring at that value.
	$H_{X}(S_{1}) = 17$
	$H_{X}(S_{2}) = 3$
	$H_{X}(S_{3}) = 26$
3. Another hash function $H_{Y}$ which also give the value in the same range 
	- Range: \[0,32]
	- For any row that you have to save/fetch, compute the hash of its sharding key using $H_{Y}$ 
	- Example
		$H_{Y}(user\_id=D_{1})=11$ 
4. Save the data of that row in immediate next server on the ring 
	Therefore, `user_id` $D_{1}$ will be stored in server $S_{1}$ 

- [x] Fast
- [x] Uniform distribution of data
- [ ] Addition/Deletion of shard (machine) should be fast

#  Addition/Deletion of shard
## Addition of shard
New Server: $S_{4}$ 
$H_{X}(S_{4})=10$ 
Only data from $H_{Y}$ = 4 to 10 will be moved to $S_{4}$ 
## Deletion of shard
If a server is deleted
Then only the data in deleted server need to be moved to the server in next position.

- [x] Fast
- [x] Uniform distribution of data
- [x] Addition/Deletion of shard (machine) should be fast

# Cascading Failure

If a server has gone down because of a particular data so when that data goes to the next server that server will also go down due to it and so on.
