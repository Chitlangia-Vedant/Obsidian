## How Kafka works

![](<../Attachment Folder/Pasted image 20260928152853.png>) 
1. Kafka internally works across multiple machines -> Kafka Brokers
2. A Topic is assigned to multiple Brokers
	- Why?
	- If every topic is assigned to only 1 Broker and Broker goes down
	- Then we will lose event
	- And there might be case where 1 Broker can't fit all the event of 1 Topic
### Basic

| Topic | Broker |
| ----- | ------ |
| A     | 1      |
| B     | 2      |
| C     | 2      |
| D     | 3      |
| E     | 4      |
![](<Attachments/Basic Kafka.svg>)
### Partition

| Topic | No. of Partition | Broker |
| ----- | ---------------- | ------ |
| A     | 2                | 1,2    |
| B     | 1                | 2      |
| C     | 1                | 2      |
| D     | 3                | 3,3,4  |
| E     | 2                | 1,4    |
![](<Attachments/Partition Kafka.svg>)
Partitions of the same topic can sit in same broker.
This solves our problem where 1 Broker can't fit all the events of 1 Topic
### Replica

| Topic | No. of Partition | No. of Replica (for each partition) | Parent Broker |
| ----- | ---------------- | ----------------------------------- | ------------- |
| A     | 2                | 2                                   | 1,2           |
| B     | 1                | 2                                   | 2             |
| C     | 1                | 3                                   | 2             |
| D     | 3                | 1                                   | 3,3,4         |
| E     | 2                | 1                                   | 1,4           |
![](<Attachments/Replica Kafka.svg>)
Replicas of the same Partition can't sit in same Broker.
This solves our problem where 1 Broker goes down with all its corresponding events
## Terms
- Broker: Machine running Kafka
- Partitions: Dividing a topic
	- At the time of config. Kafka we tell how many partitions do we want for each topic
	- Partition key: Decide which event will go to what partition and subsequently which broker.
- Topic: Type of event
- Replica
- Producer
- Subscriber
