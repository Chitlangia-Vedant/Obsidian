# How to approach a Schema Design?

## Case Study: Online Academy: Requirements
1. Online Academy have multiple batches
2. For each batch, we need to store the name, start month & current instructor
3. Each batch will have multiple classes and one class can be of multiple batches
4. Each batch will have multiple students
5. For each class store the name, date, time, instructor of the class
6. For every student, we store name, email, phone no.
7. Every student has a buddy who is also a student 
8. A student may move from one batch to another
9. For each batch a student moves to we store the date of starting
10. Every student will have a mentor
11. For every mentor, we store name, current company name
12. Store info about all mentor sessions (time, duration, student, mentor, student rating, mentor rating)
13. For every batch, store if its an Academy-batch or DSML-batch

## Step 1: Create the table
1. Find out all the nouns in the requirements
2. After identifying the noun
	- Do we have to store any data related to this noun?
3. If yes, create a table
### Name Convention
- Table name -> Plural + snake_case
- Attribute name -> Singular
### Table
1. batches
2. classes
3. student
4. instructor
5. mentor
6. mentor_session
## Step 2: Add primary key & attributes
### Primary Key
- Unique, not null
- Small in size
- Data type matters (int >>> string)
- It should rarely change
	- Because index will also change

### Table
1. batches -> id, name, start_date, type
2. classes -> id, name, date, time
3. students -> id, name, email, phone_number
4. instructor -> id, name 
5. mentor -> id, name, current_company_name
6. mentor_session -> id, date, time, duration, student, mentor, student-rating, mentor-rating

## Step 3: Identify the relationship/cardinality & Represent them

### Relationships

| Batches           | Instructor  | M-1 |
| ----------------- | ----------- | --- |
| Batches           | Classes     | M-M |
| Batches (Current) | Student     | 1-M |
| Classes           | Instructors | M-1 |
| Students          | Students    | 1-M |
| Students          | Mentors     | M-1 |
| Mentor Sessions   | Students    | M-1 |
| Mentor Sessions   | Mentors     | M-1 |
| Students          | Batches     | M-M |
### Table
1. batches -> batch_id, name, start_date, type, instructor_id
2. classes -> class_id, name, date, time, instructor_id
3. students -> student_id, name, email, phone_number, batch_id, buddy_id, mentor_id
4. instructor -> instructor_id, name 
5. mentor -> mentor_id, name, current_company_name
6. mentor_session -> mentor_session_id, date, time, duration,  student-rating, mentor-rating, student_id, mentor_id,
7. batches_classes -> batch_id, class_id
8. students_batches -> student_id, batch_id, joining_date
