# Functional Requirements
1. Restaurant system
	1. Add Restaurant with location
	2. Menu System (Skip)
2. Delivery system
	1. driver matching
	2. delivery tracking
3. Ordering and payment
# Non Functional Requirement
1. Availability for Restaurant and delivery tracking
2. Consistency for diver matching, Ordering and Payment

# API endpoint
- addRestaurant(name,location) 
- `searchRestaurent(location) -> list<restaurant> `
	- From nearest to farthest
	- Top 50
	- Pagation
- OrderFood(restaurant_id,list<food_id>)
	- Payment(order_id)
	- DriverMatching(order_id)
- Delivery Tracking(order_id)

# Database Design
## Restaurant

| Column     | Type    | Constraint  |
| ---------- | ------- | ----------- |
| id         | INT     | Primary Key |
| name       | STRING  |             |
| latitude   | DOUBLE  |             |
| longitude  | DOUBLE  |             |
| geohash_id | VARCHAR | Indexed     |
## Delivery Driver

|Column|Type|Constraint|
|---|---|---|
|id|INT|Primary Key|
|name|STRING||
|geohash_id|VARCHAR|Indexed|
## Order

| Column        | Type      | Purpose                             |
| ------------- | --------- | ----------------------------------- |
| id            | BIGINT    | Primary key                         |
| customer_id   | BIGINT    | Customer placing order              |
| restaurant_id | BIGINT    | Restaurant receiving order          |
| driver_id     | BIGINT    | Assigned driver, nullable initially |
| status        | ENUM      | Order lifecycle                     |
| total_amount  | DECIMAL   | Order amount                        |
| created_at    | TIMESTAMP | Order creation time                 |
## Payment

|Column|Type|Purpose|
|---|---|---|
|id|BIGINT|Primary key|
|order_id|BIGINT|Associated order|
|amount|DECIMAL|Payment amount|
|status|ENUM|PENDING, SUCCESS, FAILED, REFUNDED|
|transaction_id|VARCHAR|Payment gateway reference|
|created_at|TIMESTAMP|Payment creation time|
