# SQL
1. Structured data
	- Every table has a predefined structure
	- Columns, Size, Data type are fixed
	- Relationship between table
2. Normalized data
	- Minimize redundancy
	- Uses JOIN to fetch information
3. Transactions (ACID properties)
	- A -> Atomicity: Either complete or nothing
	- C -> Consistency: Data should be correct before & after transaction
	- I -> Isolation: 
	- D -> Durability: No loss once saved
# NoSQL

1. Fast writes (Uses primary storage instead of secondary)
2. Therefore, Durability is compromised

Example: Redis
# Drawback of SQL
## 1. Fixed Schema not always works

Example: If we store products info in a DB with fixed schema, we will end with most NULLs in each row.

Table: Products

| id  | title | description | price | size | brand | fabric | RAM | Author |
| --- | ----- | ----------- | ----- | ---- | ----- | ------ | --- | ------ |
- Storage wastage
- Sparse Table

We might need DB without fixed structure
	Document DB (MongoDB Elastic Search)

## 2. We often have to shard data
- Data is split across multiple machine
- JOINS across machine are impossible
