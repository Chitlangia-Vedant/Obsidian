# SQL
1. Structured data
	- Every table has a predefined structure
	- Columns, Size, Data type are fixed
	- Relationship between table
2. Normalized data
	- Minimize redundancy
	- Uses JOIN to fetch information
3. Transactions (ACID properties)
	- A -> Atomicity: Either complete or nothing
	- C -> Consistency: Data should be correct before & after transaction
	- I -> Isolation: 
	- D -> Durability: No loss once saved
# NoSQL

1. Fast writes (Uses primary storage instead of secondary)
2. Therefore, Durability is compromised

Example: Redis
# Drawback of SQL
## 1. Fixed Schema not always works

Example: If we store products info in a DB with fixed schema, we will end with most NULLs in each row.

Table: Products

| id  | title | description | price | size | brand | fabric | RAM | Author |
| --- | ----- | ----------- | ----- | ---- | ----- | ------ | --- | ------ |
- Storage wastage
- Sparse Table

We might need DB without fixed structure
	Document DB (MongoDB, Elastic Search)

## 2. We often have to shard data
- Data is split across multiple machine
- JOINS across machine are impossible
- Most SQL DB (especially older version) don't support sharding

# Types of NoSQL
## 1. Key Value Pairs
- Store info like key-value pairs like hashmap
- Eg. Dynamo DB, Redis
- When you always want to get complete value of a particular entity
- Value has no fixed type
- Consider value as nothing but a byte\[]
- All queries are based on KEY
## 2. Document DB
- Structureless
- No need to define any structure for an entity
- Each value can have its own set of attributes
- Can query on the attribute of value
- Eg. MongoDB, Elastic Search
- Values are like JSON

```
101:{
	id:101
	title:
	desc:
	ram:
	os:
	...
}
102:{
	id:102
	title:
	desc:
	fabric:
	color:
	...
}
```
## 3. Column-Family DB

Instead of storing the data row by row, they store data column by column.

1.  Faster Analytical Queries
	- Queries using same's attribute values of each entity
	- Locality of reference
2. Only interested in the value of a particular column (instead of complete entity)
3. Eg. Cassandra, HBase

**Advantage**
Compression
"....aaaaa....." ->  "....a5...."
